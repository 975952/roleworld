> 2026-09-12 凌晨整理 · 对应你最早那张阶段表。

## ① 基础聊天

| 验收点 | 状态 | 依据 | 你自己怎么验 |
|---|---|---|---|
| 角色卡能读进来 | ✅ | `local-app-check`「角色与记忆书从本机数据库读出」；内容包用例「角色卡自带立绘」「升级会刷新卡内容，但不碰对话与记忆」 | 打开应用，侧栏能看到角色；换一张卡再开一段对话 |
| 流式回复 | ✅ | 「发送消息能收到流式回复」「模型请求走的是本机配置的端点，并且带了流式标记」 | 随便发一句，看字是不是一个个出来 |
| **停止生成** | ⛔ | **你的决定**：「不需要停止按钮啊…你和别人发消息能停止吗」。按钮已从界面移除，不再作为验收项 | 生成中界面上没有停止按钮；按 `Esc` 仍会中断（不显示按钮）—— 连这个也不要的话说一声，删一行的事 |
| 错误重试不重复写入 | ✅ | `inventory-probe`「同一轮重发（同一个 turnId）不会写第二遍、不再计一次费」「重试的幂等性跨刷新有效（回执不只在内存里）」「失败那轮没有留下回执」 | 断网发一句 → 恢复网络重发同一句 → 记录里只有一条 |
| 刷新不丢记录 | ✅ | 「一轮对话保存后，重新建模型（等同刷新）仍能读出同样内容」；「存下来的回复里也没有记忆标记，刷新后依然是干净的」 | 发几句 → F5 → 记录还在 |
| 聊天保存与导出 | ✅ | `data-integrity` 存档往返 4 条：对话正文、角色卡、记忆来源元数据一字不差，**存档里不含 API Key** | 设置 → 本地数据 → 导出；换浏览器导入 |
| 不同角色数据隔离 | ✅ | `data-integrity`「甲的请求里没有乙的对话与记忆」；`inventory-probe`「两个角色各有自己的对话，互不串」「记忆书按角色归属」「已绑定会话不允许中途换角色」 | 给 A 说一句私事，切到 B 问同一件事，B 不该知道 |
| 打开以前保存的对话 | ✅ | 「隔了很久回来：旧对话能打开」「接着聊旧对话：写回同一份记录，不会另存成第二份」 | 侧栏点一段老对话，接着聊一句，看是不是还在原来那条记录里 |

## ② 上下文管理

| 验收点 | 状态 | 依据 | 你自己怎么验 |
|---|---|---|---|
| 组合角色卡 + 旧对话 + 最近消息 | ✅ | 「面板按来源分段，且分段之和与真正发出的请求一致」；`adapter-unit` 的 `composeMessages` 用例 | 点输入框旁边的「本次请求」 |
| 旧对话带多少可控 | ✅ | 「默认不限制：以前的对话全部带上」；「预算调小后，面板会写明「没带上的旧对话」而不是悄悄丢掉」 | 设置 → 模型 → 历史预算填 1000，再聊一句，看面板有没有写"未带上" |
| token 统计 | ✅ | 「对话界面显示 token 用量与费用估算」；面板每段都有字数与 token | 同上 |
| 费用估算（含峰谷与缓存） | ✅ | 费用行显示单价、时段、累计；`adapter-unit` 价格估算用例（缓存命中价、高峰翻倍） | 悬停那条费用行，看完整的计价口径 |
| **发送前**就知道要花多少 | ✅ | 「发送前预估：输入 token / 费用 / 输出上限，发之前就看得见」（含"只预估不发请求"断言） | 在输入框打字，看左下角那行数字变不变 |
| 长聊不会直接超限 | ✅ | 发送前预算检查（P2-2）：输入 + 输出上限超过上下文时**直接不发**并说明该改什么；`adapter-unit` 的 `checkContextBudget` 用例 | 把历史预算调到很大、塞很长的对话，看是否给出可操作提示 |
| 输出上限与上下文分开 | ✅ | 「本次请求」面板写 `上下文：输入 N token（占 1M 的 x%） + 输出上限 32768` | 同上 |
| 自动摘要旧对话 | ⛔ | **实测后决定不做**：历史只占请求的一小部分，固定成本（角色卡 + 记忆）才是大头；摘要既花钱又引入失真。改成长聊时明说"没带上哪几条" | 面板上那段"未带上"就是替代方案 |

## ③ 长期记忆

| 验收点 | 状态 | 依据 | 你自己怎么验 |
|---|---|---|---|
| 提取事实与偏好 | ✅ | `memory-unit` 31 项（写入、去重、改口替换、上限挤出、删除）；记忆面板用例 | 跟它说"我养了只猫叫团子"，下一轮问"我的猫叫什么" |
| 记下来源与时间 | ✅ | 「记忆能看见：点开记忆书列出条目，并标出来自哪句话」；`data-integrity` 来源元数据往返 | 打开「角色记忆」，点来源 |
| 查看 / 纠正 / 删除 | ✅ | 「记忆面板按主题分组、能折叠、显示用量」「一键清空该角色全部记忆」「记忆的「看原话」能跳回来源消息」；上限可调（设置 → 模型 → 记忆条数） | 面板里手动加一条、删一条、清空 |
| 改口能生效 | ✅ | 「改口：说一次「不喜欢了」，旧记忆被替换而不是两条并存」（断言旧说法不再出现在请求里） | 先说喜欢咖啡，再说"我现在不喜欢咖啡了"，然后问它 |
| 剧情不写成你的事实 | ✅ | 「剧情不算你的事实：模型想把剧情写进记忆会被拦下」（并告知你拦下了几条） | 演一段剧情，看记忆面板有没有混进剧情 |
| 记忆上限与挤占可见 | ✅ | 面板显示"已用 N / 上限 M"，超出时明说挤掉了最旧的 | 把上限调到 5，多聊几句 |
| 关系档案（伴侣模式）独立于记忆 | ✅ | `data-integrity`「关系档案往返后一字不差，而且和记忆书分开存」；「清空记忆不会碰它」 | 打开关系档案写一条，再去清空记忆，回来看还在不在 |

## ④ 轻量 Agent

| 验收点 | 状态 | 依据 | 你自己怎么验 |
|---|---|---|---|
| 按需搜索历史 | ✅ | 「模型主动翻查：标记不进正文，结果在下一轮交给它」；「翻得到：以前的对话被检索出来，并带出处交给模型」 | 问一句以前聊过的细节，看「本次请求」里的检索段 |
| 读取记忆 | ✅ | 记忆书按角色注入（`adapter-unit` 记忆归属用例） | 面板里那条记忆出现在请求里 |
| 主动提出记忆更新 | ✅ | `[[记住: 主题 \| 要点]]` 标记不进正文、写进记忆书；「流式回复里的记忆标记不出现在界面上（含没写完的那条）」 | 正常聊天时看是否悄悄记住了要点 |
| 找不到就说明不知道 | ✅ | 「翻不到就明说没有记录，并禁止编造」（断言提示词里出现"没有找到/不要猜测"）；诚实规则分「眼前对话」与「更早记录」两段 | 问一件从没提过的事，看它是否直说没有记录 |
| 限制工具调用次数 | ✅ | 每轮最多 2 条检索请求（`SEARCH_REQUEST_LIMIT`），`adapter-unit`/`search-unit` 有用例；写卡另有 2 次生成 + 总预算 5 次 | 「本次请求」面板会显示这轮翻了几次 |
| 引用要有出处 | ✅ | 「引用了以前的记录时会标出来，点开能看原话、点一下能跳回去」（判定保守：必须有 ≥5 字逐字相同才算引用） | 让它回忆以前的事，看回复下面那行 |
| 语义检索（向量库） | ⛔ | 明确不做：关键词检索够用，加一层只会让"找不到"变成"编得像" | —— |

## 你那张"同一套测试"的四个问题，现在的答案

| 测试问题 | 怎么被覆盖 | 依据 |
|---|---|---|
| 隔很久能否回忆 | 时间感（上次聊天几天前）+ 历史检索 + 「上次说到」 | `companion-unit` 时间感用例；「翻得到」「隔了很久回来」 |
| 用户改口后能否更新 | 记忆按主题替换；关系档案改了立刻以新的为准 | 「改口」「关系档案：改口后以新的为准」 |
| 不同角色是否串记忆 | 记忆书与关系档案都按角色存；请求里不含别人的内容 | 「伴侣模式只属于这个角色」「甲的请求里没有乙的对话与记忆」 |
| 不知道时会不会编造 | 诚实规则 + 硬规矩第 1 条「不编造共同经历」；检索为空时明说没有记录 | 「翻不到就明说没有记录，并禁止编造」「诚实规则每次都在」 |
| 记录回复延迟 / 单轮费用 / 记忆错误次数 | 台账：每轮延迟、输入/输出 token、费用（真实或估算）；「记错」标记计入台账 | 「台账：每轮记下延迟与费用，面板能看到汇总」「标记「记错」」 |
