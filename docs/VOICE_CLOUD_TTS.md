# roleworld：角色语音（云端）—— 实现与接线说明（2026-09-14）

> 结论先行：**语音只走云端**，用火山引擎「豆包语音合成模型 2.0」，经**体验卡中转**。
> 火山凭据只在**中转服务端**；客户端只发卡号 + 要念的那句话 + 音色 + 语速。
> 这一轮**没有**做真机 / 真接口联调（那要真凭据与真花钱，属单独授权），
> 所以下面凡是"没验过"的地方都逐条标了。

---

## 1. 这一轮砍掉了什么、为什么

| 砍掉的 | 为什么 |
|---|---|
| Android 系统 TTS（外壳里的 `VoiceBridge`） | 产品方向变了：本地引擎的天花板是导航播报级，再怎么修都不是"最好" |
| 浏览器自带朗读（`speechSynthesis`） | 同上；而且在 Android WebView 里它**根本不存在**（Chromium 硬编码关掉了，见 `VOICE_STICKER_WORK_2026-09-13.md` 第 3 节） |
| 本地神经 TTS 模型 | 太重（百 MB 模型 + 真机验证），不在这一轮 |
| **"云端失败就退回系统朗读"** | 关键一条：会让同一个角色有时候是情感音色、有时候是播报腔，用户根本不知道自己在听哪个。**宁可明确失败。** |

清理时**没有**动语音输入（`SpeechRecognition` / 录音 / `transcribeBlob`）—— `voice-unit` 里有专门的用例盯着这一点。

## 2. 核实过的官方接口（不是旧版，也不是 OpenAI 的 /audio/speech）

| 项 | 值 |
|---|---|
| 端点 | `POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`（HTTP Chunked） |
| 资源标识 | **`seed-tts-2.0`** ←「豆包语音合成模型 2.0」。1.0 是 `seed-tts-1.0`，不能混 |
| 鉴权（新版控制台） | `X-Api-Key` + `X-Api-Resource-Id` |
| 鉴权（旧版控制台） | `X-Api-App-Id` + `X-Api-Access-Key` + `X-Api-Resource-Id` |
| 可选头 | `X-Api-Request-Id`（排障）、`X-Control-Require-Usage-Tokens-Return: *`（回报计费字数） |
| **不要发** | `X-Api-Connect-Id` —— 那是 WebSocket 那条接口的头 |
| 请求体 | `{user:{uid}, req_params:{text, speaker, audio_params:{format, sample_rate, bit_rate, speech_rate, loudness_rate}, model, additions}}` |
| 响应 | **一行一个 JSON**（不是二进制帧协议！）：`{"code":0,"data":"<base64 音频>"}` … `{"code":20000000,"usage":{"text_words":N}}` |
| 音频 | `mp3` / `pcm` / `ogg_opus`（wav 流式会重复头，不推荐）；默认 24000 Hz；mp3 的 `bit_rate` 官方范围 64000–160000，**必须显式给**（不给时有效值可能低到 ~8k，听得出明显发闷） |

出处：官方文档 6561/2532486、6561/1598757（HTTP Chunked/SSE 单向流式）、6561/1329505（WS 双向流式）、
6561/1257544（音色列表）；并用一份逐字段对照的开源实现（`GizClaw/doubao-speech-go`）交叉核对过。
**HTTP 这条路上没有 4 字节帧头、没有 event id** —— 那套是 WebSocket 的。

## 3. 音色（`seed-tts-2.0` 配套的是 `*_uranus_bigtts` 这一族）

* 默认音色：`zh_female_vv_uranus_bigtts`（vivi 2.0）—— 官方示例自己用的就是它；
* 内置表在 `relay/voices.js` —— **它是自动生成的，别手改**（`node scripts/make-voices.cjs`）。
  数据源是官方「音色列表」的快照 `relay/voices.official.json`，生成时只保留 `*_uranus_bigtts`。
  **当前：中文 90 · 英语 42 · 其他语言 86 = 218 个**（官方全表 230，排除了 12 个名人/影视角色音色）。
  ⚠ 早先那张表只有 53 个，是**手抄**的（从一份公开实现对照着列）—— 中文少一半、英文只剩 1/6。
  手抄必然漏，所以改成了生成：**以后官方更新，抓一次正文、跑一次命令就好**。
* **不属于 2.0 的一律不放进去**（放了上游会回 `55000000`）：`*_mars_bigtts` / `*_moon_bigtts` 是 1.0，`saturn_*` / `S_*` / `DiT_*` / `ICL_*` 是声音复刻；
* 音色库随**账号开通情况**变化（没买的音色上游回 `45000000 speaker permission denied`），所以：
  * `VOLC_TTS_SPEAKERS="id=名字,id2=名字2"` —— 整表覆盖；
  * `VOLC_TTS_SPEAKERS_EXTRA="id=名字"` —— 追加；
  * **不用改代码**。控制台里有什么就往上加什么。

### 怎么扩表 / 怎么更新（2026-09-14 加）

```bash
node scripts/make-voices.cjs                       # 从快照重新生成 relay/voices.js
node scripts/make-voices.cjs --check               # 检查磁盘上那份是不是最新的（测试里跑的就是它）
node scripts/make-voices.cjs --parse <官方正文.md>  # 用新抓的官方音色列表正文刷新快照
```

生成时**排除了三类**，每条理由都写在 `scripts/make-voices.cjs` 的注释里：

1. **名人 / 影视角色音色（12 个）** —— 授权风险，不下发给用户；
   注意有几条**显示名看不出来**（Leo / Lynn / Ivy / Rachel / Scarlet / Tom），只有 id 暴露来历，
   所以匹配规则按 **id**、不按名字；
2. 官方表格里的**残缺行**（只有语言前缀、没有音色名）；
3. **不属于 2.0 那一族**的（`*_mars_bigtts` / `*_moon_bigtts` 是 1.0，`saturn_*` 是声音复刻）——
   放进去上游必回 `55000000`。

⚠ 抓官方正文这一步**要联网、而且官网有反爬**（会返回一份 4606 字节的 SHA256 工作量证明页），
隔十几秒重试即可；抓取姿势与正文位置（SSR JSON 的 `curDoc.Content`）记在本文档对应的调研笔记里。
**生成是离线的、确定的** —— 反爬只影响「刷新快照」那一步，不影响生成与测试。
## 4. 数据流

```
用户点「⋯ → 朗读」（或设置里的「试听」）
        │
        ├─ voice-core.speakableText()  剥掉 [[表情: …]] 这类标记与 markdown 符号
        ├─ voice-core.splitForSpeech() 按句切分，每段 ≤220 字（拼起来与原文逐字节相同）
        │
        └─ 每段：查缓存 ──命中──▶ 直接播（不再花钱）
                    │
                    └未命中─▶ POST {中转}/v1/audio/speech   Bearer: 体验卡卡号
                                     {text, speaker, speech_rate}
                                        │
                                        ▼
                                   中转（真凭据只在这里）
                                   · 卡校验 + **独立的语音额度**（次数 / 字符数）
                                   · 音色必须在服务端白名单里
                                   · 并发限制（每张卡 1 路 / 全局 4 路）
                                        │
                                        ▼
                             火山 TTS 2.0（NDJSON + base64 音频）
                                        │
                                   ◀────┘ 中转合成完，回 audio/mpeg + 额度响应头
```

## 5. 凭据与配置（**只在中转服务端**）

| 环境变量 | 说明 |
|---|---|
| `VOLC_TTS_API_KEY` | 新版控制台的 API Key（只发 `X-Api-Key`） |
| `VOLC_TTS_APP_ID` + `VOLC_TTS_ACCESS_KEY` | 旧版控制台（发 `X-Api-App-Id` + `X-Api-Access-Key`） |
| `VOLC_TTS_AUTH` | 想强制某一种就填 `key` / `appid` / `hybrid` |
| `VOLC_TTS_RESOURCE_ID` | 默认 `seed-tts-2.0`，不要改（除非换产品线） |
| `VOLC_TTS_MODEL` | 默认 `seed-tts-2.0-standard` |
| `VOLC_TTS_BIT_RATE` | 默认 64000 |
| `VOLC_TTS_BASE` / `VOLC_TTS_PATH` | 一般不用动 |
| `VOICE_MAX_CHARS` | 一次请求最多合成多少字（默认 400，客户端再按 220 切） |
| `VOICE_TIMEOUT_MS` | 上游超时（默认 30000） |
| `VOICE_CONCURRENCY` / `VOICE_PER_CARD` | 全局 / 每卡并发（默认 4 / 1） |

两套鉴权**不会混发**（同时发 `X-Api-App-Id` 和 `X-Api-Key` 会被上游当成配错），
`relay-check` 有用例钉着这一点。

### 检查配没配（**不联网、不花钱**）

```
GET {中转}/admin/voice/config        Authorization: Bearer <ADMIN_SECRET>
```
返回 `configured` / `missing` / `resourceId` / 音色表 / 并发与上限。
**刻意不做"真调一次"的自检** —— 语音按字符计费，一个自检按钮不该悄悄花掉用户的钱。

## 6. 额度：语音是**独立**的一份

* `quota.voice`（次数）+ `quota.voiceChars`（字符数）；`used.voice` / `used.voiceChars`；
* 与聊天的 `calls` / `tokens` **分开记**，语音不吃聊天的次数 —— 计费口径不同（语音按字符、聊天按 token），
  混在一起之后"次数还剩 3 次却发不出声"没法解释；
* 老 PG 库走 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 自动补列，不用手工动；
* 发卡 / 改卡都能带：`POST /admin/cards {..., voice: 50, voiceChars: 9000}`、`PATCH /admin/cards/:id/update {voice, voiceChars}`；
* 按天用量里也是两条线（`voice` / `chars`）。

**成本参考**（官方后付费 0.0003 元/字）：一句 100 字 ≈ 0.03 元；一条 300 字的回复念完 ≈ 0.09 元。
所以给卡配额时按"字数"想，比按"次数"想更接近真实花销。

## 7. 客户端行为（用户看得到的）

* **默认关**；打开时会弹一次**明确告知**：角色说的话会**经体验卡中转发给火山引擎**，
  发出去的是"要念的那段文字 + 音色 + 语速"，不发对话记录/角色卡/记忆书/Key。同意过的记 `voice_consent_at`，之后不再打扰。
* 「角色语音」那一行**永远看得见**：能用的条件都满足时可点，否则**禁用（灰掉）**并把原因与去处写清楚
  （例如"去「连接方式 → 使用体验卡」粘上发卡人给你的那一整行"）。
  **教训**：早先"用不了就整行藏起来"让用户以为"这个功能根本没有"（2026-09-14 实测反馈）——
  藏起来等于没有；明确禁用 + 说明原因，本身就是最好的解释。
* 探测时机：**只要有体验卡就在启动时问一次**中转有没有语音（`ensureFresh`）。
  早先写成"只在已经打开语音时才问"，而那个**用来打开它的开关**恰恰要等这次询问的结果 ——
  **死锁**，开关永远不出现。教训：**为了省一个请求而把功能变成不可达，是最亏的优化**。
* 消息菜单里的「朗读」**只在真的能出声时才出现**（打开开关 + 在用体验卡 + 中转配了火山），
  而且**每次打开菜单现算** —— 能力是异步探测的，历史消息早就渲染完了。
* 输入框上方一行状态："正在生成语音…／正在播放…"。
* 长回复**不静默截断**：按句分段，一段一段念完（旧版有个 `slice(0,1200)`，超过就没了，用户还看不出来）。
* **切角色 / 切会话 / 关开关都会停**：先取消在飞的请求（中转那头会把火山上游也掐掉），再停播放 —— 旧音频不会突然响起来。
* 失败给人话，并且标清"值不值得重试"：超时/网络/正忙会自动重试一次，额度用完/鉴权/太长不重试。
* **缓存**：键 = 文本 + 音色 + 语速 + 格式 + 采样率 + 模型 + 资源标识 + 中转。
  上限 80 条 / 24 MB，按"最久没用过"淘汰；被消息引用的（`pinned`）不淘汰 —— 这一档是给"角色发语音消息"留的。
  缓存不进导出存档（可再生成的派生数据）。

## 8. 每角色一个音色：用**稳定标识**存

* 键是角色卡的 `avatar`（文件名），**不是名字** —— 改名不该换声音（有用例钉着）；
* 默认音色由 avatar 确定性散列得到（同一角色每次一样，不同角色尽量不一样）；
* 值形状：`voice_by_card[avatar] = { speaker, speechRate }`。

### 旧设置怎么迁的（`adapter/voice.js` 的 `ensureMigrated`，幂等）

旧版的 `voice_by_card[avatar] = { rate, pitch }` 是**本机系统 TTS** 的参数：

* **语速**：同一个概念 → 按 `speech_rate = (rate - 1) × 100` 换算（rate 1.0 → 0 = 正常；范围夹在 [-50, 100]）；
* **音高**：云端接口**没有**对应项（官方只有 `additions.post_process.pitch`，单位是半音、范围 [-12,12]，
  而且我们没在真接口上验过）—— **不冒充**，直接不迁；旧值原样留在 `voice_by_card_legacy` 里（用户的数据不删），
  面板上明确写了这件事。

## 10.5 「自己配音色」这条线：声音复刻 / 音色设计（2026-09-14 核实官方文档）

预置音色之外，官方还有两条「自己配音色」的路，**它们是同一个商品**（控制台里的「音色槽位」），
共享同一个槽位的 **15 次训练/设计次数**：

| | 声音复刻 2.0 | 音色设计 |
|---|---|---|
| 输入 | 一段录音样本 | **一段文字描述**（`text_prompt` ≤200 字），也可以给一张图（≤10MB，图优先） |
| 产出 | `S_xxxxxxx` 音色代号 | 同上 |
| 接口 | 音色训练 / 音色查询 / 音色升级 HTTP | `POST https://openspeech.bytedance.com/api/v3/tts/voice_design` |

### 音色设计 HTTP（文档 `/docs/6561/2277844`，导航里叫「音色设计HTTP」）

* 鉴权：`Content-Type` + `X-Api-Key`（新版控制台）或 `X-Api-App-Key` + `X-Api-Access-Key`（旧版）+ `X-Api-Request-Id`（必须，uuid）。
  **这条接口没有 `X-Api-Resource-Id`**（跟语音合成那条不一样）。
  ⚠ 头部拼写在这份文档里是 `X-Api-App-Key`，而语音合成文档里是 `X-Api-App-Id` —— 两处不一致，别想当然。
* 请求体：`{ speaker_id, text, prompt: { text_prompt, image_prompt: { image_url | image_bytes } }, language }`
  * `speaker_id` **必须**，备注是「唯一音色代号，**控制台购买**」—— 也就是说**你得先买一个音色槽位**；
  * `text` 是**试听文本**（≤300 字），不是要合成的正文；
  * `language`：`cn=0`（默认）/ `en=1`。
* 返回**不是音频**，是 JSON：`status`（`0 NotFound / 1 Training / 2 Success / 3 Failed / 4 Active`，**2 或 4 都能拿去调 TTS**）、
  `available_training_times`（剩余可设计次数）、`demo_audio`（**Success 时给的一个 URL，一小时有效**，要留就下载）、`create_time`、`language`。
* 常见错误码：`45001001` 参数不对、`45001123` 设计次数用完（换个 speaker_id）、`55001308` 下游设计失败（可重试）、
  `45000030 requested resource not granted`（Key 认出来了但项目没开通这个服务 → 去控制台开通管理）。

### ⚠ 合成「自己配的音色」时资源标识要换（这条最关键）

* 预置 2.0 音色（`*_uranus_bigtts`）→ `seed-tts-2.0`；
* **复刻/设计出来的音色（`S_*`）→ `seed-icl-2.0`**（计费项是「声音复刻2.0 字符版」）。
  官方说明：设计出来的音色属于自定义音色，**四个 V3 接口都能用（包括我们已经在用的 HTTP Chunked 那条）**，
  而且**不需要额外的「激活/发布」步骤**（状态 2 或 4 就够）。
* 我们中转现在把资源标识**写死成一个** `seed-tts-2.0` —— 所以要用自己的音色，
  **必须先把「资源标识跟着音色走」这处改掉**（音色表里每项自带自己的 resource id），否则一定报错
  （`seed-tts-2.0` 官方文档写明只支持「豆包语音合成模型 2.0」的预置音色）。
* ⚠ `seed-icl-2.0` 这个对应关系是**官方文档写的**，但我们**没有真调过**（没有槽位，也不该在没授权时花钱）。

### 钱（控制台价格，写在这里免得又去查）

* **音色槽位是单独买的**：低档（0~50 个）约 **138 元/音色**；买得多单价低得多（几百个起降到约 38 元/音色）；
  另有更贵的「大模型精品复刻音色」档。**具体价格以控制台为准。**
* 一个槽位 = **15 次训练/设计**；合成另按字符计费。
* 换算：**给 6 个内置角色各做一个专属音色 ≈ 828 元**（按 138 那档）。这是个要先想清楚再动的数。

### 补充（第二轮调研，都是官方文档，但**没有官方 SDK / 开源实现可对照**）

* ⚠ **没有任何官方 SDK 或开源实现做过这个接口**：`doubao-speech-go` 有 `voice_clone.go` / `tts_v2.go` /
  `audio_generation.go`，**没有** voice-design；`bytedance/agentkit-samples` 里也没有音色设计的 skill；
  官方那份协议 zip 里只有 TTS 的 WebSocket 组帧代码。所以真要接，**只能照文档裸写**，没有可对照的实现 ——
  风险等级比语音合成那条高（那条至少有三个独立实现交叉验证过）。
* **这条接口没有 `55000000`**：官方错误码表里只有 `45001001`（参数）、`45001123`（设计次数用完）、
  `55001308`（下游设计失败）。**别把语音合成那条的 55000000 搬过来**（我第一版笔记里差点这么写）。
* **次数用完的错误绝不能自动重试**（`45001123` / `45001132`），只有 `55001308` 可以重试且要限量。
* `X-Api-Request-Id` 在这条接口上是**必须**（在语音合成那条是可选）；`status` 可能返回 `1 Training`，
  设计请求会**提前返回**，要轮询 `status`（或音色查询接口）到 2/4 才算好；**延迟官方没写**。
* `prompt.image_prompt` **优先级高于** `text_prompt`（两个都给，图说了算）；设计这一步只支持 `cn` / `en`。
* `S_` 是官方**保留前缀**（声音复刻的自定义音色 id 规则里明确禁用 `S_|ICL_|MIX_|DiT_|BV` 开头），
  所以「自己配音色」的 id 一眼能认出来。

**价格补充**：`0~50` 档 138 元/音色；`51~100` 档约 88 元（文档算例 80×88=7040）；`201~2000` 档 38 元；
「大模型精品复刻音色」**30000 元/音色**。⚠ **按「单次下单数量」全额累进，不累计过往下单** ——
也就是说**不能靠分批买攒到低档单价**，想拿 38 元的价，得一次下单几百个。单次最多 10000 个。

**三条容易踩的坑**：

1. **不要调「启用/激活」接口**：官方说**启用了就不能再训练/再设计**那个音色。设计要迭代就绝不能提前激活。
2. **后付费模式下，试听过的音色如果 7 天内没有被正式调用，系统会删掉它** —— 设计完要尽快真用一次。
3. 设计返回的 `demo_audio` 是**一个 URL、一小时有效**，不是音频字节 —— 所以这条接口的返回路径
   跟我们现在那条 NDJSON 音频路径**完全不同**，中转里要单独写一条。
### 我们的结论

1. **不建议现在买**：218 个预置音色已经能做区分度（用户实测已能出声），花钱的地方优先放别处；
2. 真要做，第一步是**把它当「发卡人自己的资产」**：槽位是中转运营方（你）的，不是每张卡的用户能碰的 ——
   所以设计接口只能做成**只有管理员能用**的 `POST /admin/voice/design`，客户端永远碰不到；
3. 第二步才是把「资源标识跟着音色走」改掉（十几行 + 用例，**不花钱**），这样买了槽位之后
   一个环境变量就能把 `S_xxx` 加进音色表、所有客户端立刻能选；
4. ⚠ **授权风险**：`image_prompt` 可以传真人照片照着做音色。跟复刻一样，
   **发给同学用的角色音色别用真人（尤其公众人物）的肖像/声音** —— 官方条款要求你拥有该声音的授权。
## 11. 下一轮："角色发语音消息"（形态已定，触发策略以后再设计）

用户 2026-09-14 明确了两件事：

* 想要的是**角色发一条语音消息**，**和微信语音一样**（一个气泡、带时长、**点一下才播**、能重复播）；
* "什么时候发语音、什么时候发文字"是**后面再设计**的事。

这一轮已经把地基留好了：

* `RoleWorldVoiceCloud.synthesizeToCache(text, {speaker, speechRate})` —— **只合成、不播放**，
  拿得到音频 blob 与缓存键（以后那条链路直接用，不用改这一层）；
* 缓存的 `pinned` 档 —— 消息引用的语音不参与淘汰，所以"过三天再点还能听"；
* 音色/语速/取消/额度都已经是现成的。

设计那条链路时要先回答的两个硬约束（不回答会做出做不到的方案）：

1. **浏览器不许"没交互就出声"**：页面加载后用户没点过任何地方，`audio.play()` 会被挡（NotAllowedError）。
   所以"打开就自动念"基本做不到；**微信式"点一下才播"正好绕开它**。
2. **每条回复都合成 = 每条回复都按字符计费**：0.0003 元/字，一条 300 字的回复 0.09 元。
   所以那个策略多半需要"哪些角色 / 哪些场景才发语音"的开关，并且要和体验卡的语音额度一起算。

## 12. 产品边界（2026-09-14 用户拍板）与"角色发语音消息"

用户原话：

> 我认为应该小说人物不设置伴侣，不设置语音，只有定制人物加上伴侣身份再打开语音。
> 其他都是聊天，而且伴侣应该还分为带动作的就是普通模式和软件聊天模式，就是没有动作，
> 并且可以语音，其他的都不做语音。

落成的三条规则（**只在 `app/companion-core.js` 判一次**，界面 / 提示词 / 合成前三处都调它）：

| 角色 | 伴侣模式 | 语音 |
| --- | --- | --- |
| 内置小说人物（哈利那 6 张） | ❌ 不给开（那一行禁用并写明原因） | ❌ |
| 定制角色（自己建的 / 导入的）没开伴侣 | ✅ 可以开 | ❌ |
| 定制角色 + 伴侣 + **普通（带动作）** | ✅ | ❌ |
| 定制角色 + 伴侣 + **软件聊天（无动作）** | ✅ | ✅ |

* 判定函数：`companionAccess({isBuiltin})`、`voiceAccess({isBuiltin, profile})`（`code` 分别是
  `BUILTIN_CHARACTER` / `NO_COMPANION` / `NOT_PLAIN`，`reason` 是给用户看的人话）。
* **老存档不删、不改写**：内置角色那一行即使以前开过伴侣，运行时也**不注入关系段落、不主动开口**；
  档案原样留在 kv 里（用例钉着"档案一个字都不删"）。
* 语音设置页**只列能发语音的角色**；一个都没有时写清"为什么没有、去哪儿开"（不摆一串永远发不出声的角色）。
* 点「朗读」之前也要再判一次这个角色的资格 —— 只判全局能力会出现"内置角色也能念"。

### 语音消息（微信式）的链路

```
模型在回复末尾单独一行写 [[语音]]         ← 跟 [[表情: …]] 同一套路，不引入 function calling
  → 前端**存之前**就剥掉标记（半截标记 `[[语` 也不许进正文，跟表情/记忆标记同一处清理）
  → 存完盘再**后台**合成（不然回复要等好几秒才出现）
  → 合成结果按 roleworld_turn_id 写回**那条**消息：{status:"ready", key, seconds, chars, text, speaker, speechRate}
  → 消息下面出现一个气泡：时长 + 点一下播 + 能看文字
```

几条刻意的取舍：

* **只念对白**（`voice-core.voiceMessageText` → `dialogueSegments`）：软件聊天模式下屏幕上显示的
  就是纯对白 —— 看到的和听到的必须是同一份文本，所以渲染与语音共用一份规则。
* **超过 120 字就不发语音**（默认值），**不是**截断：截断会让用户听到半句话还不知道少了什么；
  不发的话那条回复照样是文字，一个字不丢。
* 一轮最多一条语音（标记只有一个）。
* **回放不花钱**：缓存里那条被 `pinned`（不参与 LRU 淘汰），点气泡先取缓存；
  真取不到（清过缓存 / 换过设备）才按**这条语音当时**的音色重合成并回填 ——
  用户以后换了音色，旧语音也不会变声（`speaker`/`speechRate` 跟着消息存）。
* 气泡**不自动播**：浏览器不许"没交互就出声"，而微信式语音本来就是点一下才听 —— 需求与限制正好同向。
* 时长是**估算**（按字数算，不是读音频元数据）—— 气泡上的「3″」够用，但不假装精确。
* 合成要好几秒：这期间用户可能又发了一轮、甚至切走/删了会话，所以写回时**重新按轮次 ID 找那条消息**，
  不拿合成前的快照覆盖磁盘（否则会把这期间的新消息冲掉）。

### 这一轮**验到哪一步**（诚实边界）

* 本地：`voice-unit`（含"只念对白""超长不发""半截标记"）、`companion-unit`（四条边界规则）、

  "模型真的会按提示词写 `[[语音]]`"（这要看真实模型的表现，属于下一轮的真联调）。
