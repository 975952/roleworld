## P0-1 多视口布局回归 ✅

**新增** `tests/viewport-check.cjs`（25 项，已加入 `npm test`）。
自带静态服务与假模型端点，覆盖 1440×900 / 1280×800 / 768×1024 / 390×844 / 320×568。

**它当场抓到两个真实缺陷**（都已修）：

1. **平板 768px 下发送键被压成 23px 宽** —— `.send-button` 的 44px 规则只在 760px 以下生效，
   而 `.composer-footer` 是 flex，按钮被压缩。修法：基础规则加 `flex: 0 0 auto`。
2. **「记错 / 编造」按钮命中区只有 22×14** —— 鼠标都难点、触屏更点不到。
   修法：基础提到 26×24，窄屏（≤760px）提到 44×44。
   窄屏判据用**宽度**而不是只看 `(hover: none)`：实测无头 Chrome 把 hover 报成 hover，
   只按媒体查询会让手机拿到小按钮。

已按 GBK 解码后重写为 UTF-8。

**并加了一条永久防线**：`adapter-unit` 新增「仓库文本文件是合法 UTF-8」用例，
逐字节校验 `app/`、`tests/`、`docs/` 下所有文本文件。已用"故意植入坏字节"验证它真的会报错
（既有的 BOM 检查抓不到这种编码错误）。

## P0-2 / P0-3 / P0-4 数据完整性 · 压力 · 隐私出口 ✅

**新增** `tests/data-integrity.cjs`（10 项，已加入 `npm test`），自带静态服务与假模型端点。

### P0-2 存档往返

- 导出再导入后，记忆的**来源元数据一字不差**（主题 / 替换记录 / 来源对话 / 消息序号 / 时间戳 / 来源标记）；
  对话正文与角色卡名称同样保留。
- **抓到一个真隐私问题并修掉**：`exportAll()` 会把 `kv` 里的 `secrets` 一起导出 ——
  也就是**存档 zip 里带着明文 API Key**。存档是用户会随手发出去的东西，这等于把凭据送人。
  修法：导出时跳过密钥键，并在导出提示里写明"存档里不含 API Key，换机器后需要重新填一次"。

### P0-3 长对话压力（800 轮 / 1601 行 / 198 KB）

实测：写入 **5ms**、列表 **1ms**、读取 **2ms**；1600 条消息里检索 **9ms** 且命中的是目标那一轮；
界面上仍能打开、能发送、台账照常记一轮。**没有发现性能问题。**

### P0-4 隐私出口

- 请求体里**没有 API Key**；
- 甲角色的请求里**没有乙角色的对话与记忆**（角色隔离在出口处也成立）；
- 请求体里没有本机偏好字段（preferences / 教学状态 / 侧栏选择 / 称呼）；
- 请求体是干净的 OpenAI 形状：SillyTavern 时代的内部字段被适配层剥掉了；
- 全部请求只发往一个路径。

**提交**：`12db082`（含隐私修复）、`d0e4c60` 之后的清理提交

## 追加：「上次说到」+ 修掉一个真缺陷（旧对话打不开）✅

**提交**：见本文件末尾的提交列表

「上次说到」：隔了一天以上再打开一段对话，输入框上方写一行
`上次说到：<你上次说的那句原话>（上次聊天是 N 天前）`，可以「以此开头」填进输入框。
纯本地计算，**不调模型、不做摘要、不编内容**；没有记录就不显示。

**顺带抓到一个真缺陷（这次最值得说的）**：会话表里的对话名按约定不带 `.jsonl`，
而**老数据 / 导入进来的对话存储键是带 `.jsonl` 的**。打开这类对话时按去掉后缀的名字去查，
查不到 → 界面提示"这段对话已不可用"。也就是说：**导入过的旧对话其实打不开**。

- 之前那条「看原话能跳回来源消息」的用例是**假通过**：它等的"团子"其实来自上一轮对话里
  残留的回复，跳转本身失败了也没被发现；
- 修法：会话上多记一个 `storageFileName`（真正的存储键），加载时两种后缀都试一遍，
  试到哪个就用哪个，保存 / 归档 / 删除一律用同一个键 ——
  否则会出现"打得开、但新消息另存成第二份"这种更糟的情况；
- 新增两条用例：旧对话能打开并显示原话；接着聊之后**记录数不变**、
  新消息确实写回原来那份（防的正是"另存一份"）；
- 同时修了检索里"跳过当前对话"的比较（以前比的是去掉后缀的名字，等于没跳过，
  当前这段对话会被当成"历史"再塞回给模型一遍）。

## P2-1 发送前预估 ✅ / P2-2 输出上限与上下文分开 ✅

**提交**：见本文件末尾的提交列表

**P2-1 发送前预估**：输入框上方多了一行
`这次约 12.3k 输入 ≈ ¥0.0123（命中缓存 ≈ ¥0.0021） · 输出上限 32.8k`，悬停给出完整口径。

- 估法：**上一轮的真实用量**（接口回 usage 就用真值）+ 它上一句回复（下一轮会进历史）
  + 你输入框里现在的草稿。**不额外发请求、不重拼一遍提示词**（拼出来只会是另一个近似值）；
- 输入框里打字会实时更新（250ms 防抖），字越多预估越高；
- 接口没回 usage 时按字数估，并在悬停里明说"只能看量级"，不假装精确。

**P2-2 上下文与输出上限分开**：

- `task22-core` 新增 `contextLimitFor` / `outputLimitFor` / `checkContextBudget`：
  上下文是模型硬上限（本地 32k、DeepSeek 1M），输出上限是请求里写的 `max_tokens`（2048 / 32768）；
- 「本次请求」面板多一行：`上下文：输入 N token（占 1M 的 3%） + 输出上限 32768 = …，在模型上限之内`；
- **发送前检查**：输入 + 输出上限超过上下文时，**直接不发**，并在对话页写明该改什么
  （调小历史预算 / 减少记忆条数 / 换模型 / 新开一段对话），而不是等接口回 400 再让用户猜。

**顺带修了测试端的一个盲点**：假模型端点从来不回 usage，于是"按真实用量估算"这条路径
在浏览器用例里**从来没被跑过**。现在假端点会像真实接口一样在最后回一段用量（含缓存命中数），
台账与预估都按真实值走。

**测试**：adapter-unit 76 → 80（上下文/输出的取值、超限提示、脏数据）；local-app-check 54 → 55。

## P2-3 检索结果引用 ✅

**提交**：见本文件末尾的提交列表

回复下面会标一行「引用了 N 条以前的记录」，点开能看到**原话**（带出处与时间），
再点一下跳到那段对话并高亮这一句。

- 判定很保守：回复和那条记录之间必须有**一段逐字相同的原话**（至少 5 个字连续相同）才算。
  找不到就不显示 —— 宁可少标，也不让"它大概是在说这条"这种猜测出现在界面上；
- 允许改代词：模型把「我养了一只猫」说成「你养了一只猫」仍然算引用（按最长共同片段判，
  不是整句包含）；但只凭几个常用字撞车不算；
- 标注写进消息的 `extra` 里，**刷新之后仍然看得到出处**；
- 没用到的轮次不显示这个入口（有用例专门盯着"没引用也挂入口"）。
