## 第二轮开发：模式参数分层 · 记忆取向 · 截断提示（0.1.14 → 0.1.15）

用户先问"不同模式的哪些参数是否需要不同"，讨论后拍板：**按我改后的建议来** ——
不按模式硬压输出长度（剧情页/伴侣都靠提示词约束 + 记录实测），但要补上"截断提示 + 接着说"。

### ① 用途档案（purpose）：把"模式差异"从默认结果变成显式配置

以前这些差异是**没人管**的：剧情模式页一直吃着"输出上限 32768"（它只要一句台词），
而它又没有对话页那条格式指令，全靠各自绕开。现在核心层多了一张表：

| 用途 | 谁用 | 温度 | 回复格式 | 自动检索 |
|---|---|---|---|---|
| `chat` | 对话页 | 0.8 | 旁白/台词双引号 | 开 |
| `companion` | 对话页 + 伴侣模式 | 0.85 | 同上 | 开 |
| `scene` | 剧情模式页 | 0.95 | **只写自己这一小段、不替别人说话、不复述** | **关**（它有自己的场景历史） |

- 数字**只在这张表里出现一处**（`PURPOSE_PROFILES`），页面只表达"我是哪种用途"；
  覆盖也受白名单约束（表里没有的键塞不进来）—— 这正是 v0.1.3"两套配置打架"那次的教训；
- **输出上限刻意不按模式硬压**：表里留了 `maxOutput` 这个口子，等实测数据说话；
- `describeRequest`（「本次请求」面板）也跟着用途走，面板里显示的就是真正发出去的那条格式指令。

### ② 撞上输出上限：明确提示 + 「接着说」

以前完全不看 `finish_reason`：用户只看到一句半截的话，不知道是模型写崩了还是被砍了。
现在流式与非流式两条路径都会读 `finish_reason`，撞上 `length` 时：

- 在那一轮下面标一行「说到一半被截断了（撞上了输出上限）」，并给一个**「接着说」**按钮；
- 点它发出的是一句**看得见**的舞台提示（`（接着你刚才没说完的那句继续说…）`），
  不是偷偷替用户说话；
- 标记写进消息的 `extra`，**刷新之后仍然在**；
- 台账里记下"这一轮被截断了"，并按用途分开统计平均输出长度 ——
  "到底该不该限制长度"以后有数据可看，而不是我凭感觉定 300。

### ③ 记忆取向（P5-3）

记忆面板顶部多了一行「记忆取向」，按角色存：

- **平衡**（默认）：只记你的事实，剧情一律不进（原有底线不变）；
- **陪伴**：上限满时先挤剧情、再挤"说不清主题的碎事件"，最后才动
  「关于你这个人」的稳定事实（称呼/住处/年龄/工作/约定/怕的东西/饮料/食物）；
- **剧情**：剧情可以记，但**标明是剧情** —— 注入时写成 `[剧情] …`，面板里也标出来，
  而且它是最先被挤掉的（存在，但绝不冒充你的事实）。

另外加了「**说得对**」：点过的记忆在挤占时最后才动（改口替换后标记仍然跟着走）。

### 写这一轮时抓到的三个真问题

1. **归一化丢字段**：`normalizeSource` 只保留它认识的键，我新加的 `kind` / `confirmed`
   被悄悄丢掉 —— 结果是"剧情被当成事实""确认过的照样被挤掉"。用例当场抓住，已把这两个标记
   纳入归一化（并补了注释说明为什么不能丢）。
2. **挤占顺序第一版太粗**：我原以为"没主题的"会先被挤，但 `inferTopic` 对"考拉"这种短名词
   也会给出主题 —— 于是"陪伴取向"和"平衡取向"行为几乎一样。改成真正的区分：
   陪伴取向下按"主题是否属于关于你这个人的那几类"排序，平衡取向只把剧情提前、其余按新旧。
3. **无头环境点错按钮会挂死**：新测试第一次跑就卡住不动 —— 我点的"第一个 `.memory-actions` 按钮"
   其实是**组标题**上的「清空整组」，它弹 `confirm()`，而无头环境里没人点确定。
   给行内按钮加了独立类名 `memory-confirm`，测试只点它。

## 第五轮：修掉顶栏「记忆」按钮点不到（0.1.17 → 0.1.18）

用户照着我写的用法说明去点，回了一句「**看不到记忆**」。核代码，是真的点不到：

`app/index.html` 顶栏那颗 `<button data-action="open-memories" … hidden>` 里的 `hidden`
是 P0 骨架从原来那份生产前端整段拷过来的，而**移植之后没有任何代码把它摘掉**——
`app.js` 只在开关面板时改它的 `aria-expanded`，从不碰 `hidden`；`styles.css` 里还有一条
`[hidden] { display: none !important; }` 把它按得死死的。
于是右侧「记忆」栏（0.1.14 才刚做完的那套）**唯一的用户入口是内部函数 `TASK21.openMemoryPanel()`**，
界面上根本点不到。无头 Chrome 探针实测：`hidden=true`、`display=none`、`0×0`。

**为什么九十个端到端用例一个都没抓到**：它们打开这个面板用的全是
`window.TASK21.openMemoryPanel()`；而 `element.click()` 对隐藏元素**照样会触发事件**，
所以"按钮能不能被用户点到"这件事从来没被验过。教训写进用例里了。

修法与守卫：

- 去掉那颗按钮的 `hidden`（并留注释说明为什么它不能再带上）；
- `adapter-unit` 新增静态守卫「主要入口按钮不能带 hidden」：按 `data-action` 抓按钮标签，
  带 `hidden` 直接判红，同时要求存在 `close-memories` 与 `open-memories` 的处理分支；
- `local-app-check` 新增「顶栏「记忆」按钮看得见、点得开」：先查几何
  （`hidden` / `computed display` / 尺寸 / 是否在视口内 / `elementFromPoint` 有没有被遮住），
  再用 **CDP `Input.dispatchMouseEvent` 发一次真鼠标点击**（不是 `element.click()`），
  点开后必须列出真实记忆书，最后用关闭按钮收回并断言右栏真的关上了。

顺带修掉一个发布脚本的漏项：`app/about.html` 正文和状态 JSON 里各写了一份版本号，
但它**不在 `scripts/set-version.cjs` 的同步范围内** —— 这次升 0.1.18 时它没跟着动，
全量测试当场变红（`关于页的状态 JSON …版本号与 package.json 一致`）。现已纳入同步并加写入后自检。

五种宽度实测（1440 / 1280 / 768 / 390 / 320）：按钮 48×32、都在视口内、顶栏无横向溢出；
`#topbarTitle` 的宽度在"有按钮 / 没按钮"两种状态下**一模一样**（123px / 窄屏 140px），
也就是说这次改回来没有挤到标题。

**测试**：adapter-unit 98 → 99、local-app-check 61 → 62；九个套件合计 **315** 项全绿。

## 第八轮：让角色记得"之前发生了什么" + 原著剧情（0.1.20 → 0.1.21）

### ① 事件记忆：新增 `[[事件: …]]`（机制）

原来只有一条通道：`[[记住: 主题 | 要点]]`，而且 `classifyMemory()` 会**确定性地拒收**带剧情特征的

- 存进同一个「自动记忆」书，但 `rw_source.kind = "event"`；
- **注入时一律带 `[此前发生]` 前缀**（`task22-core.buildSystemPrompt`），事实条目不带前缀 ——
  这是用户那条底线「真实信息和虚构剧情分开存」的落点：事件记得住，但绝不冒充"关于你的事实"；
- 事件**不参与"同主题替换"**：昨天去了图书馆、今天又去了，是两件事，合并等于抹掉历史；
- 上限满时挤占顺序：剧情 → **事件** → 其他（"你是谁"的事实最后走）；

  也不会把事件写进记忆。
- 刻意**不把主题词「剧情」当成事件**：剧情仍走记忆取向那道闸 —— 端到端用例里模型正是用
  `[[记住: 剧情 | *你挥动魔杖挡住了巨龙的攻击*]]` 试图把剧情塞进记忆的，那条用例现在仍然红得住。

## 第九轮：体验卡 —— 让不会配 Key 的同学也能用（0.1.21 → 0.1.22）

用户的原话：「能不能像发体验卡一样通过某种加密的方式提供这个 api key，我的同学有些不会用」。
先说清楚一件事：**把真 Key 加密塞进客户端是不行的** —— 应用最终必须拿明文 Key 去请求服务商
（放在鉴权头里），抓包就能看到；而且给出去就收不回来，只能整个换 Key、把所有朋友一起断掉。
所以"体验卡"必须是一张**能限额、能到期、能吊销的凭证**，真 Key 留在服务端。

### ① 中转服务 `relay/`（OpenAI 兼容，SSE 原样透传）

- `relay/server.js`：`POST /v1/chat/completions`（流式/非流式都透传）、`/v1/models`、`/card/quota`、
  `/healthz`，以及带口令的管理接口（发卡 / 列卡 / 停用 / 启用 / 吊销）；
- `relay/store.js`：账本三种后端（memory / file / cloudbase），入库的是 **sha256(卡号)**，
  不是卡号本身；文件后端"写临时文件再改名"，断电不会把整本账写坏；
- 卡的校验一律给人话：`CARD_UNKNOWN`（卡号抄错或已收回）、`CARD_DISABLED`、`CARD_EXPIRED`、
  `CARD_NO_CALLS`、`CARD_NO_TOKENS`，并说明上限是多少；
- 响应头回 `x-rw-card-calls-left / -tokens-left / -expires`，被拒时也给 —— 客户端能显示"剩 0 次"。

**两条硬规矩（写进代码 + 有测试守着）**：
1. **不记正文**：日志只有 时间/卡 id/模型/是否流式/状态/耗时/用量；
2. **账本只有哈希**：列卡接口也不返回卡号。

### ② 发卡工具 `scripts/card-cli.cjs`（本机跑，只跟管理接口说话）

`issue --label 小明 --calls 200 --days 30` 会打印**一段可以直接转发给同学的话**（卡号 + 三步用法 +
隐私说明）；另有 `list / disable / enable / revoke / quota / text`。
卡号只在发卡那一次返回（账本里只有哈希），发完就得复制走。

### ③ 应用侧：设置里多一行「体验卡」

- 同学粘**卡号**、**卡号@中转地址**、或**整条 `#card=…` 链接**都认（最后一种点开就自动配好）；
- 「使用体验卡」= 把接口指向中转 + 把卡号存进密钥位（`api_key_custom`）+ 查出剩余额度；
- 那一行下面写清了取舍：走中转时对方能看到「用了多少」，但中转服务端不记录聊天内容；
- 卡号存在 secrets 里，跟 API Key 同一条规矩：**不进导出存档**。

### ④ 测试

- 新增第 10 个套件 `tests/relay-check.cjs`（**20 项**）：起一个假上游 + 真的中转，覆盖
  卡的六种结局、用量记账、SSE 逐字节一致、CORS 预检与响应头暴露、模型白名单、上游报错透传、
  管理接口关闭，以及上面那两条硬规矩（日志里找不到用户那句话、账本里找不到卡号明文）；
- `adapter-unit` +3：三种粘贴形式（含整条链接的解码）、`looksLikeCard`、额度文案；
- `local-app-check` +1：用假中转把"粘贴 → 自动配置 → 显示剩 4 次"整条链路跑一遍。

**测试**：十个套件合计 **359** 项全绿。

### ⑤ 部署这一关卡在账号上（要用户出手）

`tcb cloudrun deploy roleworld-relay --source relay --port 8787` 的返回是：

```
× [CreateCloudRunServer] 云托管资源未开通
```

也就是这个 **体验版**环境没有开通云托管（容器）。要真正发卡给同学，二选一：
① 在 CloudBase 控制台**开通云托管**（体验版通常要先转成按量计费的付费环境）；
② 把中转放到别的常开主机上（自己的服务器 / 有公网 IP 的机器）。
**云函数不是好替代**：事件式调用没有流式，而且请求/响应体有大小上限，而本应用默认把整段历史
都发出去，长对话必然撞上限 —— 所以 `relay/scf.js` 只作为降级方案留着，并在文件头写明这一点。

1. **`response.clone()` 用错了时机**：我原本在异步回调里才 clone 响应去写缓存，

### 补记：上下文预检的"本地端点"口径，以及我自己踩的一个坑

P2-2 的预检需要知道上下文上限。本地/自定义端点各家不同（8k / 32k / 128k 都有），
拿一个数字硬猜会误拦，所以加了设置项「本地端点上下文（token）」，默认 32768。

**加完立刻踩坑**：这个默认值被当成了"所有模式"的上限，套到 DeepSeek 官方（1M）头上，
于是"输入 + 输出上限 32768"必然超过 32768 —— **每一次发送都被自己的预检拦下**。
`local-app-check` 在几分钟内就把它抓出来了（20 多条用例同时变红，全部指向"根本没发出请求"）。

修法：这个设置只对本地/自定义端点生效（`contextBudgetOptions` 里先判断是不是已知云端模式），
并补两条守卫：`adapter-unit` 断言"官方 1M 不该被拦"，`local-app-check` 断言面板上写的上下文是
`1000000` 而不是设置里的 32768。**这类"设置悄悄改变了主流程"的问题，只有端到端用例拦得住。**
