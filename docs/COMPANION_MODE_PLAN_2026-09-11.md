## 0. 先说清楚：伴侣模式和现在的角色聊天差在哪

不是"更甜一点"，而是四件很具体的事。下面这张表左边是你真正会提的要求，
中间是现在已有的，右边是原本缺的：

| 你会提的要求 | 现在有什么 | 原本缺什么 |
|---|---|---|
| "它得一直记得我们是恋人" | 角色卡里写的关系 + 模型碰巧记下的记忆 | 一份**你亲手写、模型不许改口**的关系档案 |
| "隔了半个月回来，它得知道过了半个月" | 有记忆、有历史检索 | 模型**不知道今天几号**，也不知道上次聊是什么时候 |
| "它不能拿内疚留我" | 完全没有约束 | 一条明确的硬规矩（写进每轮提示词，也写在界面上让你能核对） |
| "我每天都聊，别烧太多钱" | 有台账（延迟/费用/token） | 每轮多带多少**发之前**就看得见；没有预算上限 |

## 1. 已经做了什么（今晚，已测）

### P5-1 关系档案（你亲手写的那一份）✅

- 位置：「角色记忆」面板 → **关系档案**按钮。
- 内容：关系（朋友/知己/恋人/家人/师长/自定义）、他怎么称呼你、你怎么称呼他、
  关系起点（纪念日）、「你们之间的事」（最多 8 件，一件一行）。
- **存在哪**：`kv` 的 `companion:<角色>`。刻意**不放进记忆书**——
  你写下的真实信息和模型自己记的东西分开存，所以**「清空记忆」不会碰它**。
- **可核对**：面板上实时显示"每轮会多带约 N 字（约 M token）"，
  发之前就知道代价，和台账同一个口径。

### P5-2 时间感 + 那几条硬规矩 ✅

打开伴侣模式后，每轮系统提示里会多一段（固定部分 **332 字 ≈ 200 token**，满配 **775 字**）：

- 关系 / 称呼 / 认识多少天 / **今天是几号** / **上次聊天是几天前**（本地算，不额外调模型）；
- 硬规矩 6 条，界面上的「伴侣模式会额外遵守这几条」列的就是**同一份文字**（不另写宣传文案）：
  1. 不编造共同经历：只有档案里和这段对话里真有的，才算"记得"；
  2. 不用内疚或冷淡留人（点名禁掉"你都不理我""我等了你很久"这类话）；
  3. 不索取陪伴，不拿"你会不会离开我"试探；
  4. 不劝你疏远现实里的人；
  5. 被认真问到时承认自己是程序；
  6. 你改口时以新说法为准。
- **自检**：面板里会拿最近 20 条回复查一遍内疚话术，命中就把原话点出来。
  只报告、**不改写**模型的话——过滤会误伤正常表达，而且拦住了不等于没发生。
- 语言跟着卡走：英文卡拿英文段落（中文段落会把英文角色带跑，这个坑之前踩过）。
- 关掉 = **一个字符都不多发**（有用例断言）。

**成本口径**：这段文字每轮都一样，属于可缓存前缀；你之前核对过的官方口径是
"缓存命中的输入约为未命中的 1/50"，所以这几百字在账面上是小数点后的量级。
真实花费以台账里的实际值为准，不用信我的估算。

**测试**：`tests/companion-unit.cjs` 21 项（纯逻辑：归一化、上限、时间感、语言、内疚话术识别）；
`local-app-check` 新增 8 项（默认关闭 / 段落进请求 / 每个角色各一份 / 改口生效 / 关掉即停 /
自检 / 英文卡 / 存档往返不丢）。

## 2. 建议接着做的（等你点头）

按"对你最有感 × 风险最低"排序：

### P5-3 记忆取向：伴侣模式下更看重"关于你的事实"

- **做什么**：给每个角色一个记忆侧重开关。伴侣模式默认偏向
  *人物 / 偏好 / 关系 / 正在发生的事*，剧情类只留在对话里不进记忆；剧情模式反过来。
  再加一个「这条说得对」按钮：你确认过的记忆**永不被上限挤掉**。
- **对准**：你的测试项「用户改口后能否更新」「不知道时会不会编造」。
- **成本**：0 次额外调用（`classifyMemory` 已经在做事实/剧情分类，只是换个取舍方向）。
- **风险**：低。分类是启发式的，可能漏掉一条该记的——所以宁可少记，不误删你说过的话。

### P5-4 陪伴预算：每天都在聊，得有个上限

- **做什么**：设置里给一个"每月最多花多少"的软上限（默认关闭）；
  到 80% 时在顶栏提示一次，到 100% 只提示不拦（拦不拦你定）。
  台账加一页"这个月聊了几天 / 平均延迟 / 单轮费用 / 被标'记错'几次"。
- **对准**：你阶段⑤里写的"成本可控"。
- **成本**：0 次额外调用。
- **风险**：低。默认关闭，不影响现在的行为。

### P5-5 「上次说到」

- **做什么**：隔了几天再进来，输入框上方显示一小条本地汇总：
  "上次说到：猫粮换了牌子（3 天前）"。点一下可以把它当开头发出去。
- **对准**：你的测试项「隔很久能否回忆」；而且这条**不花一分钱**（纯本地读）。
- **成本**：0 次调用。**没有记录时就明说"没有记录"**，不编。
- **风险**：低，但"汇总得像不像话"很考验取哪几条——建议只取最后 2~3 条你真实说过的话，不做摘要生成。

### P5-6 输出长度与节奏（和你清单里的 P2-2 是同一件事）

- **做什么**：伴侣模式默认把单轮输出上限调小（例如 300~500 token），
  旁边留一个"今天想多说点"的临时开关；输出上限与上下文预算在界面上分开显示。
- **对准**：日常闲聊的成本与语感（长篇回复在伴侣场景里反而假）。
- **风险**：中——会改变现有回复长度，属于体验偏好，**需要你先确认默认值**。

### P5-7 主动消息（默认关闭，技术上有硬限制，必须先说清楚）

- **能做什么**：只在**桌面端且应用正在运行**时，才可能做到"按你设定的时间发一条"；
  网页端做不到（浏览器不允许后台唤醒），只能在你打开应用时提醒。
- **必须的约束**（如果你要，我会做成这样）：每个角色单独开关、默认关闭、
  每天最多 1 条、可设免打扰时段、发送前显示预估费用、
  文案里**不出现**"你多久没来了""我一直在等你"这类话（自检用例会盯着）。
- **我的建议**：**先不做**。它是这个功能里唯一有可能伤到人的部分，
  而且做不到"真的主动"（应用没开就什么都不会发生），性价比最低。

## 3. 明确不做（红线）

| 不做 | 原因 |
|---|---|
| 亲密度数值 / 好感度等级 / 连续打卡 | 关系不是一个可以自动累加的数字，做出来就会变成"刷" |
| "她生气了""她在冷落你"这类状态机 | 正是你说的冷落惩罚 |
| 内疚话术、索取陪伴、劝你疏远现实关系 | 你的底线；现在写成了硬规矩 + 自检 |
| 自动摘要历史对话 | 实测历史只占请求的 7~24%，固定成本才是大头；摘要既花钱又会引入失真 |
| 向量库 / 多智能体 | 关键词检索已经够用，加一层只会让"找不到"变成"编得像" |
| 伴侣模式默认打开 | 默认关闭，只有你自己点了才会多带那 300 多字 |

## 4. 怎么验证（沿用你那张表的同一套测试）

每一项都跑这四个问题，并记录**回复延迟 / 单轮费用 / 记忆错误次数**：

| 测试问题 | 伴侣模式下怎么答 |
|---|---|
| 隔很久能否回忆 | 时间感（上次聊天几天前）+ 历史检索；用例覆盖"今天/昨天/72 天前" |
| 用户改口后能否更新 | 记忆按主题替换；关系档案改了立刻以新的为准（用例断言旧称呼不再出现） |
| 不同角色是否串记忆 | 档案按角色分别存；换角色表单是空的（用例断言） |
| 不知道时会不会编造 | 诚实规则 + 硬规矩第 1 条「不编造共同经历」；检索为空时明说没有记录 |
