### 修掉的两个缺口

`saveTurn()` 现在带一个**轮次标识（turnId）**：同一次发送用同一个标识，重发同一句沿用同一个标识；

### 阶段②-1 已完成：上下文预算 + 请求内容可见

**先核对了官方上限**（2026-09-11，[官方定价页](https://api-docs.deepseek.com/quick_start/pricing/)）：
DeepSeek V4.1 Flash / V4 Pro **上下文 1M tokens、最大输出 384K**。
结论：**"长聊直接超限"在 1M 窗口下基本不会发生**，真正的毛病是另一件事——
旧对话写死"只带最近 16 条"：**16 是条数不是预算**，长聊时早期内容被无声丢掉。

| 做了什么 | 说明 |
|---|---|
| **旧对话默认全部带上** | 新增 `planHistory()`。默认 **0 = 不限制**：以前的对话全部发送，不丢内容。依据：官方上下文 1M；且已发过的内容下次按**缓存命中**计价（官方价表 $0.003 vs 未命中 $0.15 每百万 token，约 1/50）。"只带最近 16 条"是 4k 上下文时代的做法，这套配置不需要 |
| **想省才截断** | 只有用户自己填了正数上限才按预算从最近往前截断，且**无论预算多紧至少保留最近 4 条** |
| **绝不静默丢弃** | 一旦真截断，面板里写明：`未带上：更早的 N 条消息（约 X tokens）——旧对话预算为 Y tokens` |
| **预算可调** | 「设置 → 模型」新增"旧对话预算（token）"，**留空即不限制** |
| **请求内容可见** | 输入框上方一个很淡的「本次请求」入口，点开按来源分段：角色卡各段 / 世界设定 / 每本记忆书 / 回复格式要求 / 旧对话 / 本轮输入，各段字符数与 token；平时完全看不见，关掉即消失 |
| **逐字节自检** | 面板自带一致性核对：分段之和必须与真正发出的请求**逐字节相等**，不等就当场标红说"这份数字不可信"。这条已写成自动化断言 |

**实测一份真实角色的开销结构**（用户自己的 Harry 卡，一句话的请求）：

| 部分 | tokens | 占比 |

| 系统提示（角色卡 + 两本记忆书 + 回复格式） | 1322 | **87%** |
| 样例对话 | 124 | 8% |

所以"压缩旧对话省钱"收益极小 —— 这也是不做摘要的量化依据。

## 阶段③ 第三批已完成：真实信息与虚构剧情分开存

这是用户定的**第一条底线**。以前模型只要写 `[[记住: …]]` 就会被存下来 ——
包括"*你挥动魔杖挡住了巨龙的攻击*"这种剧情。现在**在纯逻辑层确定性拦下**，不靠模型自觉。

| 做了什么 | 说明 |
|---|---|
| **剧情特征识别** | 角色扮演排版符号（`*动作*`、`（动作）`、`【旁白】`）、故事动作（拔出魔杖/挥剑/施法/击败）、故事世界物件（魔杖/副本/战力/密室…）、剧情记帐（第几章/上一幕） |

## 3. 阶段② 推进建议（唯一主线）

用户的要求是：**"先让每次请求的内容可检查、费用可观察，再决定哪些地方值得增加复杂度。"**
现有工程已经有一半（费用可观察=事后估算），缺的是另一半（请求可检查）。所以阶段②按这个顺序做：

### ②-1 请求检查器（先做，是后面所有步骤的验收工具）

- 在对话输入条附近放一个**极低调的入口**（如 `#chatCostLine` 旁边一个「查看本次请求」文字按钮），
  打开一个只读面板，列出**上一次真实发出的 payload**：按段渲染
  `[系统提示]`（角色卡字段 / 卡内 lore / 各本记忆书命中条目，**标注每段来自哪本书/哪张卡**）、
  `[样例对话]`、`[历史 N 条]`、`[本轮输入]`，每段给 **字符数 + 估算 token**，末尾给合计。
- 数据来源不需要新造：`integration.js:1805` 的 `buildGeneratePayload()` 返回值里已经有完整 `messages`，
  存一份到 `liveState.lastPayload` 即可。
- **验收**：面板里显示的分段之和 == 请求体里 `messages` 的实际内容（逐字节比对），
  且面板永不发起新请求、不落盘、不含 Key。
- **隐私**：面板只在本机渲染，不外发；导出存档时**不包含** payload 快照。

### ②-2 上下文分层预算 + 旧对话摘要

现在的组合是"系统提示 + 样例 + 最近 16 条"，**16 是写死的条数，不是 token 预算**。
建议改成显式的分层预算，按优先级从高到低：

1. 角色卡常驻段（`system_prompt` / `description` / `personality` / `scenario` / 卡内 constant）——不可裁；
2. 当前角色自己的记忆书命中条目——不可裁，但**超过各自上限时按上限截断并标注**；
3. 「自动记忆」书（上限 50 条）——按新近度截断；
4. 最近 N 轮原文——按 token 预算回填，直到预算用尽；
5. **旧对话摘要**（新做）——预算还够时补一条 `[更早的对话摘要]`，超出部分的原文丢弃。

摘要的落地方式（这是阶段②里唯一需要新增逻辑的部分）：

- **按会话文件缓存**在 `data/kv/`（键如 `summary:<avatar>:<fileName>`），记录
  `{ coversUpToLine, text, updatedAt, model }`；只对**已经被挤出窗口**的消息做增量摘要，
  不重算全量；摘要本身可以被用户查看和手动重写。
- 摘要请求复用同一份模型配置，但**必须可关**（设置里一个开关），并在请求检查器里
  单独列出"这次摘要花了多少"。
- **验收**：长对话（>200 轮）不出现"直接超限"；旧内容在摘要里仍有痕迹（可问"我们最早聊了什么"）；
  请求检查器能看清这次到底带了哪些段、各多少 token。

### ②-3 token 与费用的"发送前预估"

- 现在是**发完才知道**。改成发送前就显示：本次请求输入预估 token + 预估费用（含缓存命中假设），
  与上一轮的实际值对照。
- 输出侧要和上下文侧分开：`max_tokens: 32768` 是**输出上限**，跟输入是否超模型窗口是两件事；
  超限要在**发送前**给可操作提示（"本次输入约 X k，可能超过该模型窗口"），而不是发完只弹一句"请重试"。
- **明确写清算法口径**：接口回 `usage` 用真值，没回按字数估算（`pricing.estimateTokens`：中文×0.6、其他/4）。
  当前这套口径是诚实的，继续保持，但要在面板里显式标注"估算/实测"。

### ②-4 成本可观察

- 已有：单轮 `#chatCostLine` + 峰谷按北京时间 + 可在设置覆盖单价。
- 建议补：**本次对话累计**与**今日累计**（只存本机 `kv`，不外传），以及"哪一段吃掉了钱"
  （系统提示 vs 记忆书 vs 历史 vs 摘要）——这正好复用 ②-1 的分段统计。

**阶段②先不做**（用户已经明确）：向量数据库、多 Agent、把 1M 上下文塞满。

## 修掉一个由提示词造成的真问题：模型不敢认下眼前这句话

**用户实测抓到的**（原文）：

> 用户：我一般买三文鱼味的猫粮
> （哈利正常回应）
> 用户：我上次说买什么猫粮来着
> 哈利：The only thing I've heard you say about cat food is the salmon thing, **about ten seconds ago. Before that I've got nothing.**

**问题**：那句"十秒前的话"就在**同一段对话**里、就在上下文里，模型却说自己"之前什么都没有"。

**根因是我写的提示词**：诚实规则只写了"凡是你这里没有依据的，一律说不知道"，
又看到检索结果写着"没有找到以前的相关记录" —— 于是模型把**眼前的对话**也当成了"没有依据"，
开始怀疑并否认自己刚看到的内容。

**修法**（核心是把两件事分开讲，而不是让模型装失忆）：

```
[Honesty]
先把两件事分开：
① 你们**正在进行的这段对话**是你亲眼看到的事实，可以直接引用、
   可以直接说「你刚才说过…」，不要怀疑它、也不要说自己不知道。
② **更早以前的对话**不在你眼前，只能靠下面 [History search] 的记录说话。
   记录里有的才引用；记录里没有的，就照实说「这边没有更早的记录」——
   绝对不要为了显得连贯而编造过去的细节、地点、时间或承诺。
换句话说：**不是要你装失忆，是要你别编**。
```

配套改动：
- 检索为空时的说明改成"在**更早以前**的对话里没有找到（这只说明更早的记录里没有，
  你们这段对话里刚说过的话仍然算数，不要否认它）"；
- 检索结果开头标明"更早以前的对话"；
- `[History access]` 里补一句"当前这段对话本来就在你眼前，不用去查"。

**测试**：`search-unit` 13 → **15/15**（新增"诚实规则必须区分眼前的对话与以前的记录"、
"翻不到时的说明不能说成整段对话都没记录"）；`local-app-check` **36/36**
（诚实规则那条用例补上"必须说明眼前的对话算事实、不要否认刚说过的话"）。

> 教训：**"不要编造"和"不要装懂"是两件事，不能只写前者的反面。**
> 只强调"没依据就说不知道"，模型会把真实的、就在眼前的信息也一起否掉。

## 修掉：英文角色因为玩家说中文就切成中文

**用户实测抓到的**：内置的 Harry 卡（英文卡）在用户用中文提问时，回复**中途切成中文**，
用户直接问「怎么变成中文了」。

**查出来的两个原因**：

1. **卡上没有语言约束**。内置包里六张卡，**五张**都写了 `language: en`，
   唯独 `Harry Potter (EN).png` 没写 —— 它 765 字的 system_prompt 里一次 "English" 都没提到。
   名字带 `(EN)`、tags 里写着"英文"，但那只是给人看的标签，**提示词里没有任何约束**。
2. **语言读取只认一种写法**。代码只读 `data.extensions.task29.language`（CCv3 嵌套），
   顶层的 `language` 字段被忽略；而当初给内置卡加语言标记时是用顶层字段加的。

**改了三处**：

| 改动 | 说明 |
|---|---|
| 语言读取兼容两种写法 | 先看 CCv3 的 `data.extensions.task29.language`，再退回顶层 `language`（含 `zh-cn` / `english` 这类写法） |
| 语言约束写强 | 从 "always reply in English" 改成明确写死：**即使玩家用别的语言（比如中文）说话，也用英文回答；绝不为了配合玩家切换语言**。中文卡同理 |
| 给那张卡补上语言标记 | 新增 `scripts/set-card-language.cjs`，只替换 PNG 里的角色数据块、**图像字节原样保留**。`Harry Potter (EN).png` 补成 `en`，`packs/` 与 `app/packs/` 两份都同步 |

**顺带踩到的坑**：这张 PNG 同时带了 `chara`（V2）和 `ccv3`（V3）**两个**数据块，
只改一个的话读取方取到另一个，语言标记等于没写 —— 脚本已改成两个都改并逐个校验。

**测试**：`adapter-unit` 63 → **68/68**（语言标记两种写法、英文卡必须写明"玩家用中文也要说英文"、
中文卡同样禁止切语言、没设语言的卡不硬塞约束、语言要求必须钉在最后）。

### 追加修正：语言约束被后面的格式指令盖过去了

补上语言标记后**仍然中英混着来**（旁白英文、台词中文）。原因：语言要求写在系统提示的**中间**
（角色卡那几段之后），而"旁白/台词格式"指令在**最后** —— 模型对最后一条规则最敏感，
语言要求被盖过去了。

修法：`buildSystemPromptWithFormat` 把语言要求**钉在整个系统提示的最后一行**（格式指令之后），
中间那处保留。并写成断言：最后一条非空规则必须是 `[Language]`。

### 追加：包自带的卡怎么更新

内容包的设计是"只补缺失、绝不覆盖已有"，所以补了语言标记的卡**不会自动生效** ——
用户库里存的还是旧卡。加了"包升级时刷新包自带卡内容"的机制：

- 只刷新带 `pack_source.id` 匹配标记的卡（安装时打上），**用户自建卡一律不动**；
- 只换卡本身，**聊天记录、记忆书、加入时间、收藏状态全部保留**；
- 触发条件是内容包版本变化（`packs/index.json` 与 `pack.json` 从 1 → 2）。


### 追加第二次修正：语言要求放**两头**，并做成可当场核对

按"钉在最后"改完仍然出现**旁白英文、台词中文**（用户第二次实测）。
说明只靠一处位置不够 —— 模型对**开头**（"你是谁、说哪种语言"这种身份级约束）
和**结尾**（最后一条规则）都敏感，夹在中间的容易被忽略。

现在语言要求出现在**三处**：系统提示开头、角色卡那几段之后、以及格式指令之后的最后一行。

同时新增**当场可核对**的显示：「本次请求」面板顶部会写：

- 有语言要求时：`语言约束（3 处）：[Language] This character speaks English only…`
- 没有时：`语言约束：这张角色卡没有设语言…所以模型会跟着你的语言走。`

**为什么加这个**：前两次都在"猜是不是卡片没生效"。现在打开面板就能看到
**真实发出去的那段文字** —— 有就是有，没有就是没有，不用再猜。

`adapter-unit` **68/68**（新增断言：开头必须是语言要求、全篇不少于 3 处）。

### 追加第三次修正：卡内容其实一直没被刷新（真实原因）

面板给出了决定性证据：

> 语言约束：**这张角色卡没有设语言**（没说只说中文或只说英文），所以模型会跟着你的语言走。

即：包里那张卡已经补上了 `language: en`，但**用户库里存的还是旧卡**。
前两次改提示词之所以"时好时坏"，一部分原因就是**卡片本身一直没变**。

**为什么加了刷新机制还是不刷新**：刷新条件要求卡上带 `pack_source` 来源标记，
而**旧版本装的卡根本没有这个标记** —— 所以永远跳不到刷新分支。

**修法**：加一次性"内容修正种子"（`packs:seed-version`）：

- 老存档第一次跑新版应用时，即使包版本号没变，也**补刷一次**包自带卡内容；
- 刷完写入种子版本，之后不再重复刷；
- 刷新只换卡本身，**对话记录、记忆书、收藏状态、加入时间全部保留**（已写成端到端断言）。

**测试**：`local-app-check` 36 → **37/37**（新增端到端：造一份"缺语言标记、无来源标记"的旧卡 +
一段对话 + 一本记忆书 → 重跑内容包安装 → 断言卡拿到了 `language: en`、来源标记补上、
**收藏与加入时间保留、对话与记忆书一字未动**）。

全套：`adapter-unit` **68/68**、`memory-unit` **25/25**、`search-unit` **15/15**、
`inventory-probe` **14/14**、`local-app-check` **37/37**。

> 教训：**"改了源文件"不等于"用户那边生效了"。** 本地优先的应用里，
> 数据一旦落进用户的库，源文件的改动需要一条明确的迁移路径 —— 否则改了等于没改。

## 阶段④ 第三批已完成：每轮指标台账

用户要的三个数字现在都有了，并且**记错与编造只由人手动标记**。

| 记什么 | 说明 |
|---|---|
| **首字延迟 / 整轮延迟** | 从发送到第一个字（体感速度）、到完整回复（等待时间），毫秒级 |
| **单轮 token 与费用** | 接口回 `usage` 用真值，否则按字数估；以及这一轮的估算费用 |
| **这一轮的系统行为** | 写了几条记忆、替换了几条、被拒收几条（剧情）、历史检索命中几条、主动翻查几次 |
| **记错 / 编造** | **只能由用户点按钮标记**，机器绝不自动判定；再点一次取消 |
| **很准** | 同一套机制里留了一个正例标记，将来可以用来看准确率 |

**怎么用**：每条助手回复旁边有两个很轻的按钮「记错」「编造」——
平时几乎看不见（鼠标移上去才显形），点一下计入台账并高亮，再点取消。
「本次请求」面板顶部汇总最近 20 轮：平均首字延迟、平均整轮延迟、费用合计、记忆写入条数、
检索命中条数、记错次数（含占比）、编造次数。

**两处刻意的设计**：

1. **标记按轮次 ID 关联，不按下标**。消息列表会被截断、切对话、翻页，
   按下标标记会标到别的轮次上——那比不标记更糟。轮次 ID 同时写进消息与台账，两边对得上。
2. **没有样本时显示"—"，不显示 0%**。空台账里的"0% 错误率"是假象。
