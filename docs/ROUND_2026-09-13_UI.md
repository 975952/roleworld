## 二、本轮改了什么（按用户三项）

### ① 统一角色 / 记忆 / 关系入口

**改前**：三个入口各管一块 —— 「角色记忆」弹窗（模型自己记的）、右侧常驻「记忆书」栏
（你手写的）、「关系档案」弹窗（伴侣模式）；顶栏角色名是死的 `<h1>`，改同一个角色的信息
要先分清这几个概念。**没有**任何"角色面板"。

**改后**：
- 顶栏**角色名变成按钮**（带小头像与下拉箭头）→ 打开统一**角色面板**，三个分页：
  - **设定**：角色卡原文（名字 / 它是谁 / 性格 / 场景 / 开场白 / 示例对话 / 标签 / 文件 / 来源），只读；
    能改的几项指到已有入口（角色管理里按角色改语言与侧栏，设置 → 记忆里改开关与上限）。
  - **记忆**：原来的「角色记忆」原样搬进来（来源、确认、改写、删除、记忆取向、手动加一条）。
    **自动记下的（自动记忆）与你手写的记忆书分开显示**，不混。
  - **关系**：原来的「关系档案」整份表单搬进来，标题与说明写明**只对这个角色生效**。
- 顶栏「记忆」→ **一步落在记忆页**（两个平台一致）；桌面上同时把右侧常驻记忆栏打开
  （那是这个按钮原来的行为，不因为合并入口而消失）。
- 实现上原来的 `#memoryPanel` / `#companionDialog` **保留成两个分页（id 不变）**，
  渲染函数、存储、事件全部复用 —— 所以"原有记忆能力一条没少"。

### ② 设置页按用户任务重组

**改前**（7 个分区）：外观 / 对话 / 角色管理 / 布局 / 模型 / 关于 / 本地数据，
其中「模型」一页里塞了服务商、接口地址、模型名、API Key、思考模式、体验卡、
**角色语言、自动记忆、事件记忆、记忆上限**、旧对话预算、本地端点上下文、单价、生成参数。

**改后**（8 个分区）：外观与布局 / 回复偏好 / 记忆 / 角色管理 / **连接方式** / **高级设置** / 关于 / 本地数据。
- **连接方式**：自己配置 API / 使用体验卡 两个单选，各自显示自己的表单与状态。
  当前是哪一种**从真实状态推导**（密钥像卡号 = 体验卡），不新增标志位，避免"界面说一套、实际走另一套"。
  切回自己的 API 只改 provider/endpoint，**不删体验卡**；本机还留着卡号 + 中转地址时，
  切回体验卡是**一键**（不用重新粘）。体验卡占的是「自定义云端服务」那个密钥格 ——
  这件事写在状态行里，不默默覆盖用户的自定义 Key。
- **回复偏好**：发送方式 / 思考模式 / 角色语言 / 回复风格。
- **记忆**：自动记忆 / 记住发生过的事 / 每个角色最多几条（**写明它是全局默认**），
  外加「打开记忆」直接进当前角色的记忆页。
- **高级设置**：旧对话预算 / 本地端点上下文 / 输出上限 / 温度·top_p / 单价覆盖。
- 布局并入「外观与布局」；保存与自检按钮留在「连接方式」。
- **没有动任何默认参数值**（模型名、温度、输出上限、上下文都与原来一致），也不按模式压回复长度。

### ③ 消息操作放在消息旁边

**改前（核实结论）**：**没有消息菜单**。每条消息只有「记错 / 编造」「引用」「接着说」三样；
复制、编辑、重新回答、从这里开分支、失败重试**都不存在** —— 所以这是新增，不是改造。

**改后**：
- 每条消息的 meta 里一个「⋯」：**手机常显**（不依赖悬停）、桌面悬停或键盘聚焦才显形；
  命中区走 `--tap`（渲染后 ≥44px）。
- 用户消息：复制 / 编辑 / 从这里开分支；助手消息：复制 / 重新回答 / 从这里开分支。
- **编辑**：改最后一条用户消息 → 就地改写（条数不变，并提示可点「重新回答」按新问题重答）；
  改**更早**的消息 → 不悄悄改写历史，改成「从这一句开新分支，并把改动带过去」，界面上写明这件事。
- **重新回答**：走同一条发送链路，但上下文截到那条回复之前、**不新增用户消息**；
  落盘写成**新版本**（`swipes` 追加、`swipe_id` 指向它），旧版本用 `‹ 1/2 ›` 切回，
  **`mes` 始终等于选中的那一版**，所以下一轮上下文自动用当前版本。
- **从这里开分支**：新建一个**对话文件**（保留原对话头部元数据，正文截到这一条），
  原对话一个字都不改，提示写明「原对话没有改动」。
- **失败重试**：失败那一轮渲染一张卡片（原话 + 真实原因 + 「重试」）。
  因为失败的一轮**整轮都没落盘**（用户话与回复是一起写的），重试是"原样再发一次"，
  不会产生重复的用户消息。

## 四、顺带修掉的两个真问题

1. **设置里那个"体验卡/服务商切换"会误用凭据** → 现在切回自己的 API 会**跳过体验卡占用的密钥格**，
   自动挑一家"确实存着 Key"的服务商；体验卡会被覆盖这件事写在界面上，不静默发生。
2. **落盘会把每条消息写两遍**（数据完整性）：新写的用例断言"重新回答只替换一条、条数不变"，
   当场发现 `buildSavePayload(session.lines, …)` 返回的是"整段旧对话 + 追加项"，
   拿它再拼消息 → 条数 3 → 6。现在只借它的"补头"逻辑，正文由调用方给。
   另外 `choice-menu` 只认 `.memory-modal select`，关系页搬出该容器后下拉会退回系统原生样式
   —— 也当场被用例抓到，已显式补上 `#companionDialog select`。

## 六、补完的数据验收：真实界面「导出 → 干净环境导入」

上一版报告把这一条列成"剩余问题"，现已补齐，并单独成一个套件
`tests/archive-roundtrip.cjs`（已接进 `npm test`，12 个套件）。

**隔离性**：这套用例自己起静态服务、自己开一份全新的浏览器 profile；
静态服务把 `packs/index.json` 换成空清单，所以环境里**只有合成角色**，
内置内容包不参与 —— 既不会写到内置角色身上，也不碰任何真实用户数据。

**造出来的合成数据**（全部通过界面操作）：
- 一条有两个版本的回复，并**切回第 1 版**（也就是非默认的那一版，`swipe_id = 0`）；
- 从「第二句：分支起点」那条**历史消息**开的分支，分支里还有一句独有内容；
- 编辑最后一条用户消息（改成「第三句：改过之后」）之后**继续聊**了一轮。

**走的界面路径**：设置 → 关于 →「导出存档」（真的落下一个 .zip）→ 用应用自己的
`resetAll()` 清成干净环境 → 设置 → 关于 →「导入存档」（真点那颗按钮；
无头环境没有系统文件对话框，只把"打开对话框"换成 CDP 注入同一个 input 的文件，
之后 change 事件走的仍是应用自己的导入代码）→ 应用自动刷新。

**核对结果（14/14 全过）**：

| # | 验收点 | 结果 |

| ④ | 对话段数与导入前一致（原对话 + 分支都在） | PASS |

## 七、剩余问题（下一轮可做）

1. ~~导出再导入后的版本 / 分支关系~~ —— **已完成**，见第六节（`tests/archive-roundtrip.cjs`，14/14）。
2. **那条偶发已经定位到根因并修掉**（不是"重跑就过"，下面是触发条件与结论）：

   - **失败现象**：用例「同学点体验卡链接」走到最后一步报
     「开场走完了却没记标记，下次还会弹」（断言 `card_welcome_seen === true` 时读到旧值）。
   - **触发条件**：`onboarding.js` 的 `finish()` 原来是**先 `close()` 关浮层、再落盘**，
     而中间隔着两次 await（读体验卡状态 + 写本机设置）。关浮层是"这一步完成了"的对外信号，
     自动化（和用户的眼睛）等的都是它 —— 于是在"浮层已消失、写还没落地"之间有一个真实窗口。
     命中窗口就红，命中不到就绿：所以它偶发、且与机器当时的 IO 快慢有关，重跑常过。
   - **是否影响产品**：**影响很小但不为零**。落在窗口里的用户如果正好刷新或关掉标签页，
     下一次打开会再弹一次体验卡开场（幂等、不丢数据，只是多走一遍）。没有数据损坏风险。
   - **修法**（产品侧改顺序，不是把测试睡久一点）：`finish()` 改成**先落盘再 `close()`**，
     于是"浮层没了" ⟺ "标记已经写下去了"，两侧都不再有窗口。
   - **回归守卫**：用例里新增一条断言，直接钉住这个**顺序**——
     浮层消失的那一刻立刻读设置，`card_welcome_seen` 必须已经是 true；
     谁把顺序改回去，这条立刻红（不是靠等待时间掩盖）。
   - **证据**：修复前连跑 3 次全绿（说明它是罕见竞态，不是稳定失败，光靠"一次全绿"确实不能说它没了）；
     修复后连跑 2 次全绿，且现在由**构造**保证不再有窗口。
3. **设置页里「关于」与「本地数据」的分工**（用户后续清单第 3 条）：
   建议合并成「数据与备份」，显示最近导出时间、角色/对话数，导入前预览冲突 —— 本轮未动。
4. **角色与对话的全局搜索**、**剧情模式模板与"我在参与/我是导演"标识**（后续清单 1、2）—— 本轮未动。
5. 伴侣模式的关系页在 1280×800 下滚动区约 600px，字段多时需要滚动；
   面板已加高到 `min(88vh, 860px)`，如果还要更紧凑，下一轮可以把"亲近度/冷落/主动消息"
   折成一组可折叠项。
