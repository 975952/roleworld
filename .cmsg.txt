feat(test): 数据完整性 / 长对话压力 / 隐私出口自查（P0-2 ~ P0-4）

新增 tests/data-integrity.cjs（10 项，已加入 npm test），自带静态服务与假模型端点。

P0-2 存档往返完整性
- 导出再导入后，记忆的**来源元数据一字不差**：主题、替换记录、来源对话名、
  来源消息序号、时间戳、来源标记（模型自记/用户手写）
- 对话正文与角色卡名称同样逐字保留
- **发现并修掉一个真隐私问题**：`exportAll()` 会把 `kv` 里的 `secrets` 一起导出，
  也就是**存档 zip 里带着明文 API Key**。存档是用户会随手发出去的东西，
  这等于把凭据送人。修法：新增 `EXPORT_KV_SKIP = ["secrets"]`，
  导出时跳过密钥键；导出完成提示改为"存档里不含 API Key，换机器后需要重新填一次"。

P0-3 长对话压力（800 轮 / 1601 行 / 198 KB）
- 写入 5ms、列表 1ms、读取 2ms（实测量级）
- 1600 条消息里检索耗时 9ms，且命中的是目标那一轮
- 界面上仍能打开、能发送、台账照常记一轮

P0-4 隐私出口自查
- 请求体里没有 API Key（用假的 sk- 字符串断言）
- 甲角色的请求里**没有乙角色的对话与记忆**（角色隔离在出口处也成立）
- 请求体里没有本机偏好字段（preferences / 教学状态 / 侧栏选择 / 称呼）
- 请求体是干净的 OpenAI 形状：SillyTavern 时代的内部字段
  （chat_completion_source / custom_url / task22_engine）被适配层剥掉了
- 全部请求只发往一个路径，没有"发往别处"的迹象
